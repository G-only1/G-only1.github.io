Firewall Lab

Objective:

In this activity you will configure and test Windows Defender using the GUI and PowerShell. We will run services, scan for open ports using nmap, create and analyze firewall rules, enable firewall logging to see allowed and blocked traffic, spoof a scan source address and document our findings.

Instructions:

Part 1 - Preparation

  1. Start your Windows VM and change hostname:

    1. Right click the Windows Start Menu and select system

    2. Under About, click “Rename this PC.” Change the PC to be named Win01-(FIRSTNAME).

  2. Reboot your computer to apply changes. After reboot, open PowerShell and run the “whoami” command

  • Deliverable 1: Take a snip of the output of the “whoami” command showing the properly renamed system name.
  1. Make sure Microsoft IIS is running, and can be reached on your Kali VM by browsing to the Windows IP address in your Kali browser.

Part 2 - Download nmap and Inspect Firewall Rules

  1. https://nmap.org/download.html - Download latest stable release for Windows on the host machine, & copy it into your Windows VM’s download directory. Ncat MUST be installed!

  2. Remember to choose the install location as the downloads folder in the destination folder:

    EX: C:\Users\outreach\Downloads\

  1. Go through the install setup wizard for Npcap with default options, and finish the installation.

  2. Enter PowerShell and start ncat on port 8082 by entering:

  • ncat -l 8082 -k -v

  • IF PROMPTED, ALLOW BOTH PRIVATE AND PUBLIC ACCESS!

  1. Inside the Windows search bar, search for and open Windows Defender Firewall with Advanced Security.
  • Deliverable 2: Navigate to Windows Defender Firewall -> Advanced Security and locate the TWO newly created ncat inbound rules. Provide snips of both.
  1. From your Kali VM, attempt to ping your Windows VM:

  • Ping -c1 (Insert-Windows-VM-IP)

  • A Successful ping should result in the result shown in the screenshot above. If you see 100% packet loss, figure out why you may not be able to ping.

  • Deliverable 3: SNIP a successful ping from Kali to Windows. Once successful, describe what, if anything, you had to change to allow a successful ping. Why do you have to make that change?

    I didn't have to change anything for the ping to succeed.

Part 3 - Enabling and Reading Windows Firewall Logs

By default, Windows Firewall does not log allowed connections or dropped packets. We are going to enable these logs, generate traffic from our Kali box, and read the log file.

  1. In Windows Defender with Advanced Security, navigate to properties.

  1. Turning on Logging Option 1 - GUI: You will see three tabs: Domain profile, Private profile, and Public Profile. Do the following steps for all tabs:

    1. Click Customize under the logging section

    2. Set Log dropped packets to Yes

    3. Set Log successful connections to Yes

    4. Make note of the log file path (default: C:\Windows\System32\LogFiles\Firewall\pfirewall.log)

    5. Click OK

  1. Turning on Logging Option 2 - PowerShell:

    1. Open Powershell as Administrator

    2. Set-NetFirewallProfile -Profile Domain,Private,Public -LogBlocked True -LogAllowed True -LogFileName “C:\Windows\System32\LogFiles\Firewall\pfirewall.log” (Make sure if you have a different default log file you change the Log File Name above.

  2. Verify the settings applied: Get-NetFirewallProfile | select-Object Name, LogBlocked, LogAllowed, LogFileName

  • Deliverable 4: Take a screenshot of the results of the command above, showing that in all three domains, the Firewall will log dropped and successful connections.

    Now we are going to generate some logs from our Kali Box and inspect our Windows Firewall logs.
  1. On your Kali VM:
    1. Ping your Windows VM 3 times
    2. nmap -p 80,443 <WINDOWS IP>
  2. On your Windows VM:
    1. Open Powershell as an Administrator
    2. Read the last 30 lines of your firewall log: Get-Content C:\Windows\System32\LogFiles\Firewall\pfirewall.log | Select-String "today's date in this format yyyy-mm-dd” | Select-Object -Last 40
  • Deliverable 5: SNIP the output of your log file, highlight in one color the logs from your pings, highlight the nmap logs in another color.
  • Deliverable 6: Investigate: Are there any connection attempts in your log file that got dropped? Inspect your firewall rules and see if you can figure out why or why not those connections were dropped. Describe the connection, the relevant rule, and what that means.
    There were no connection attempts that got blocked by the firewall

Part 4 - Blocking HTTP through Windows Firewall

  1. Create a new rule in Windows Defender Firewall with Advanced Security called “Blocky” with a description of your first and last name. This new rule should block all inbound HTTP Traffic for domain, private, and public.
  • Deliverable 8: Snip the block firewall “blocky” rule.
  1. On your Kali VM, test the connection to see if you can access your webpage. It should not work, proving the “blocky” rule is working.
  • Deliverable 9: Find the Log entry for this failed connection.
  1. Open Windows Internet Information Services (IIS) application, and in the “sites” folder, right click “Default Web Site” and select “Edit Bindings…”.

  1. Click on the port 80 binding for the website, and edit the connection to use port 8888 instead of port 80 for connections.

  2. On your Kali VM, try connecting to the site through port 8888.

  • http://(WindowsIP)/(WebPageFileName):8888

Deliverable 10: Troubleshoot and reflect. If the connection does not work, explain why. Think about what the firewall currently knows about port 8888. Describe what change you made to fix it, and explain why that fix was necessary.
The connection did not work initially because port 8888 does not have a rule allowing it and is blocked by default. I made a new rule to allow port 8888 called Unblocky. The connection worked after I added the unblocky rule because port 8888 was being allowed by unblocky.
6. Successfully connect to the website using the new port on the Kali VM.

  • Deliverable 11: Find the entry for the successful connection in your Windows Firewall Logs.

    Please go back and delete your custom rules. Turn off your VM when you are done.
