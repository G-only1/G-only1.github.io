Module 11 - Intro to AWS, Linux Server

Intro to AWS - Linux Server

Objective:

In this lab you will provision a Linux web server on Amazon Web Services (AWS), configure it to serve a webpage over HTTPS using a self-signed certificate, and deploy a Web Application Firewall (WAF) to detect and block common web based attacks. By the end of the lab you will have hands-on experience with cloud infrastructure, basic Apache configuration, TLS/SSL concepts, and web application security.

Step 1: Accessing the Learner Lab

  1. Login to your Kali VM. Go to your Champlain College email inbox. You should have received an email from AWS Academy in the last week.

  2. Setup an AWS Learner Lab Canvas account using the link sent to your Champlain College email address.

  3. Go to Modules - Learner Lab

  1. Click “Start Lab” and wait a few minutes as it loads.

  1. The AWS Console icon above the terminal window will turn from yellow to green once the environment is running. Note: It commonly takes 3-5 minutes to load.

  1. Click the AWS icon with the green dot to launch the AWS Console.

Step 2: Launching an Amazon Linux Server

  1. Use the Services search bar and search for “EC2”.
  2. Click EC2 to get to the EC2 Dashboard.

  1. Click on the Instances “Instances” Menu on the left pane.

  1. Click the orange “Launch Instances” on the right.
  2. On the “Launch an Instance” screen:
    1. Name your web server “your_name Web Server”
    2. Select Quick Start Amazon Linux as the OS Image (default)
    3. Select t2.micro as the Instance Type
    4. Key Pair (Login)
      1. Choose “vockey”

        NOTE: This key is like a password - you will need access to it to log into your server.
    5. Network Settings:
      1. Create security group
      2. Check allow SSH traffic from anywhere 0.0.0.0/0
      3. Check Allow HTTPS traffic from Internet
      4. Check Allow HTTP traffic from Internet
      5. Leave defaults for “Configure Storage” and “Advanced Details”
    6. You should be all set and can go ahead and click Launch Instance.
  3. You should get a green screen showing the instance was launched. It will take a few minutes before it is accessible.

Step 3: SSH into your Server

  1. Go back to the AWS Learner Lab Browser Tab and click “AWS Details”.
  2. Click “Download PEM” to download the vockey key file (called labsuser.pem). Pay attention to where it is downloaded to.

  1. On your Kali VM, open a terminal
    1. Change your directory to the location where labsuser.pem is stored. Use the following commands:
      1. cd <path to labsuser.pem>
      2. ls -la labsuser.pem (to ensure the file is there)

  1. Leave this window open and within the same directory.
    3. In the AWS console, go to EC2 -> Instances -> Instances and click the checkbox next to the running instance.
    4. In the lower pane, note the “Public IPv4 Address”.
    1. NOTE: The “Open Address” link will not work- please don’t click that.

  1. In the terminal, enter the following command:
    1. sudo ssh -i labsuser.pem ec2-user@<your_public_IP>
      1. Ec2-user is the default user for AWS Amazon Linux instances.
        2. Replace <your_instance_public_IP> with the address from section D of this step.
      2. For any key usage prompts, answer “Yes”.
      3. From here, you should have access.

Step 4: Setup your Server as a Web Server

  1. Elevate your privileges so that you can install software:
    1. sudo -i
  2. Install Apache Web Service (aka httpd) with:
    1. yum -y install httpd
  3. Start the httpd service:
    1. systemctl start httpd
    2. Note: if you want to check the status of the Apache server (httpd), run the following command. It should show as Active.
      1. systemctl status httpd
  4. Change your directory to the web root directory using the following command:
    1. cd /var/www/html
  5. Use the nano command to create a default web page called “index.html” inside of this directory.
    1. nano index.html
    2. Inside the document, add the following:
<html>
<head>
	<title>
		<your_name> webpage
	</title>
</head>
<body>
	<p> This is <your_name>'s Webpage from an AWS Instance - and it's live on the Internet!!!</p>
</body>
</html>

1. Save the file.
6. From another device, open a new tab and enter in the Public IP of your AWS Server Instance.
7. You should see the message you wrote in the “index.html” file.

Step 5: Enable HTTPS with a Self-Signed Certificate

In this step, you will configure your web server to use HTTPS by generating a self-signed SSL/TLS certificate.

  1. Install the SSL module for Apache
    1. Yum -y install mod_ssl
  2. Generate a self-signed certificate and private key.
    1. openssl req -x509 -nodes -days 365 -newkey rsa:2048 -keyout /etc/pki/tls/private/myserver.key -out /etc/pki/tls/certs/myserver.crt
    2. You will be prompted to fill in some fields. Enter whatever you'd like as long as it is easy to identify your submission from others. For Common Name, enter your server's Public IP address.
  3. Edit the SSL configuration file
    1. Nano /etc/httpd/conf.d/ssl.conf
    2. Find the following two lines and update them to point to your new certificate and key:
      1. SSLCertificateFile /etc/pki/tls/certs/myserver.crt
      2. SSLCertificateKeyFile /etc/pki/tls/private/myserver.key
  4. Restart Apache to apply the changes:
    1. systemctl restart httpd
  5. Test your HTTPS connection by navigating to your public IP address using https://<your_public_IP>
    • Deliverable 2: Submit a screenshot of your webpage with HTTPS running (include the address bar).
    • Deliverable 3: Find the details of your self-signed cert in the browser and submit a screenshot.

Step 6: Installing a Web Application Firewall

  1. Install Modsecurity and the OWASP Core Rule Set
    1. Yum -y install mod_security && yum -y install mod_security_crs
  2. Verify the configuration
    1. Grep -i “SecRuleEngine” /etc/httpd/conf.d/mod_security.conf
  3. Confirm the OWASP CRS rules are loaded
    1. Ls /etc/httpd/modsecurity.d/activated_rules/
  4. Restart Apache to load the modules
    1. Systemctl restart httpd
  5. Simulate a SQL Injection Attack
    1. From your host machine (not your VM), open a browser and navigate to the following URL:
      1. https://<your_public_ip>/?id=1' OR '1'='1'
      2. Deliverable 4: Snip a screenshot of the attempted attack (include the address bar).
  6. Simulate a Cross-Site Scripting (XSS) Attack
    3. From your host machine (not your VM), open a browser and navigate to the following URL:
    1. https://<your_public_ip>/?search=<script>alert(‘xss’)</script>
    2. Deliverable 5: Take a screenshot of the attempted attack (include the address bar).
  7. Simulate a Directory Traversal Attack
    5. From your host machine (not your VM), open a browser and navigate to the following URL:
    1. https://<your_public_ip>?file=../../etc/passwd
    2. Deliverable 6: Take a screenshot of the attempted attack (include the address bar).
